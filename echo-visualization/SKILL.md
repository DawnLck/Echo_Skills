# 可视化

`renders/` 里有 9 个已经调好版式、配色和深浅色的模板，全部实测可跑；
`scripts/` 里有两个出 PNG 文件的脚本。
你的工作是：挑一个最贴题的，把数据和文案换掉，而不是从空白页开始拼 CSS。
怎么选、选几个、要不要混用、要不要干脆不画，都由你判断。

## 先回答一个问题

**这张图要回答什么用一句话说不清的问题？**

答得上来就画，答不上来就别画。图不是用来装饰答案的，是用来承载
文字承载不了的东西 —— 位置关系、数量级差距、形状、路径、同时性。

几个常见的「其实不用画」：结论就一个数、三行字能说完的对比、
用户只是要个解释、信息不足以可靠作图（这时说清楚缺什么，比编一张图诚实）。

反过来，用户已经点名要图、要 AntV、要图解的时候，别再反问要不要画。

## 可以选的表达方式

| 方式           | 擅长什么                                       | 代价                       | 模板                                                          |
| -------------- | ---------------------------------------------- | -------------------------- | ------------------------------------------------------------- |
| **AntV G2**    | 精确数值：趋势、分布、排行、相关性、多系列比较 | 依赖 CDN，要写降级         | `renders/01-chart-g2.html`                                    |
| **G2 组合图**  | 柱+线、双 y 轴、正负条件色、阈值/现价/成本参考线、点标注 | 同上；写法和 01 不同，见下面清单 | `renders/08-combo-dual-axis.html`                             |
| **AntV G6**    | 关系拓扑：依赖、血缘、调用链、组织、知识图谱   | 同上，且布局选错就乱       | `renders/02-graph-g6.html`                                    |
| **AntV S2**    | 大表与透视：几十行以上、要下钻或交叉汇总       | 重，少用；小表用下面的表格 | 无模板，参照 G2 的降级写法                                    |
| **纯 SVG**     | 流程、机制、架构、判定分支、时间线             | 不会自动折行，文字要自己控 | `renders/03-diagram-svg.html`                                 |
| **HTML / CSS** | 少量关键数字、排行、数据表                     | 几乎没有，首选             | `renders/05-metrics-cards.html`、`renders/07-data-table.html` |
| **可交互 H5**  | 状态如何推进、参数如何改变结果                 | 要保证首屏静态可读         | `renders/04-interactive-h5.html`                              |
| **原图叠加**   | 结论依赖原图里的真实位置、数量、边界           | 原图像素不许动             | `renders/06-image-overlay.html`                               |
| **PNG 文件**   | 用户要「一张图片」：发群、贴文档、放 PPT，或复刻一张 matplotlib 风格的图 | 不能交互；要有中文字体 | 任一 render + `scripts/export-png.sh`；离线 / 无浏览器用 `scripts/combo_chart.py` |
| **只写文字**   | 以上都不成立的时候                             | ——                         | ——                                                            |

这是菜单不是判定树。可以混用（比如一张 G2 加一张排行表），
也可以一个都不用。真要组合，最多两块，且第二块要回答另一个独立问题 ——
并排两张讲同一件事的图，读者只会更累。

选库的直觉：**数值精度靠 G2，拓扑关系靠 G6，能不用库就别用库。**
一张图里同时出现「两种单位 / 柱+线 / 关键点位虚线」中的任意一项，就别改 01，直接从 08 开始。
四个 KPI、一列排行、一张十行的表，用 HTML 写又快又稳又好看，
搬出图表库反而是过度工程。

## 怎么用这些模板

1. 挑一个最贴题的，**完整读一遍**（大多 200 行以内，08 稍长；都有注释说明哪些该改、哪些该留）。
2. 换掉数据、标题、导语、图例、脚注。
3. 保留三样东西：`:root` 的 token 块、降级分支、窄屏 media query。
4. 包进 renderer 块输出。

`renders/00-shell.html` 是所有模板的共同底座 —— 纯排版、无图形。
做纯结构化输出，或者要自己拼一个新形式时从它开始。

模板里的标题、文案、示例数字全是占位。**必须按当前任务重写**，
尤其是标题：写结论（「开放 API 在 7 月反超 SDK」），不要写图名（「调用量趋势图」）。
读者的眼睛第一个落在标题上，那是最贵的一行字，别浪费在描述图种上。

## 让它看起来是设计过的

模板已经把这些做掉了，自己写新形式时照着来：

- **一套 token 走到底**。颜色全部从 `:root` 取，深色模式在 `prefers-color-scheme` 分支里
  重定义同名变量。这样所有输出看起来像出自同一套系统，而不是每次换一个风格。
- **单序列用墨色加一个强调色，多序列才动用分类色板**。
  默认就上五颜六色是业余感的主要来源；颜色要用来区分，不是用来点缀。
  按含义上色（正绿负灰、超阈值标红）属于「区分」，可以用，但辅助系列要做浅，让主线压在上面。
- **细线，不要网格框**。横向分隔线留着，竖向网格线去掉 —— 竖线会把视线切断。
  例外是**有含义的竖线**：阈值、现价、成本、事件日这类参考线要画，用虚线 + 各自颜色 + 文字标签。
- **数字用 `tabular-nums` 并右对齐**，个位对齐了才能竖着比大小。
- **留白给够**。挤满的版面没有重点，密度本身就是一种噪音。
- **图例手写成 HTML**，别用图表库生成的 —— 排版可控，而且永远不会被画布裁切。

## 几条实测踩出来的坑

这些不是理论，是这套模板调试时真实翻过的车：

- **`<meta charset="utf-8">` 必须写**。宿主若不带 charset 头返回，中文会整页变乱码。
  顺带把 `<meta name="viewport" content="width=device-width,initial-scale=1">` 也写上，
  否则移动端按 980px 渲染，窄屏 media query 一条都不会触发。
- **G2 的入场动画必须关，而且要关在 mark 上**：
  `.animate('enter',{ type:null, duration:0 })`。
  Chart 构造参数里写 `animate:false` 不生效。宿主若离屏或后台渲染，
  requestAnimationFrame 被节流，只会强制出一帧 —— 坐标轴是静态的画得出来，
  线还停在动画第 0 帧，结果就是一张「只有坐标轴、一条数据线都没有」的空图。
  G6 则是构造参数 `animation:false`，那个是有效的。
- **不同单位不要共用一根 y 轴**。把「万次」和「百分比」画在一起，
  量纲小的那条会被压成贴着轴的直线，看着像「没变化」，其实是图错了。
  要对比就拆成上下两张小图、先归一化成指数，**或者用 08 的双轴**：
  右轴那组 mark 写 `scale.y = { independent:true, domain:[固定值] }`，两边 domain 都固定，
  并让两轴的参考点对齐（如左 50% ↔ 右 0）。用户给的图本来就是双轴时，照双轴画，别擅自拆成两张。
- **SVG 里的文字不会自动折行**。框内只放短单行，解释性句子放到图外的 HTML 里。
  竖向流程比横向耐缩放：横图在 360px 宽会把 13px 文字压到 6px。
- **CDN 会失败，降级要先写好**。G2/G6 用 `onerror` 标记 + `try/catch`，
  失败时渲染同数据的表格或结构化列表。任何情况下都不能留下一块空白。
- **交互必须首屏静态可读**。第 0 步直接渲染、结论写在导语里，
  不动鼠标也拿得到答案。只做 hover 高亮或入场动画的「交互」不值得加。
- **分步演示的步骤要由模型函数生成**，不要手写一串步骤数组 ——
  换算法时只改那一个函数，渲染和控件都不用动。
- **G2 v5 组合图的几个硬坑**（08 已处理，自己写时照抄）：
  · x 是连续数值、又要在任意位置画参考线时，柱子用 `rect`（自己算 `x`/`x1`），不要用 `interval`
  —— interval 的 x 是类目，3674 这种不在类目里的值落不上去。
  · text 的旋转写 `style.labelTransform:'rotate(90)'` + `labelTransformOrigin`；
  `rotate`、`transform` 在 5.4.8 写了也不转（外层 transform 会被覆盖）；旋转后别用 `textBaseline:'top'`，字会被裁。
  · classic 主题给轴文字、轴线、网格、线条都预乘了透明度，`labelOpacity` / `gridStrokeOpacity` /
  `strokeOpacity` 不显式写 1，颜色 token 会再被淡一次，网格线几乎看不见。
  · 只想要「整 50 一个刻度」时用 scale 的 `tickMethod` 直接给刻度数组，比 `tickFilter` 可靠。
- **出 PNG 时中文最容易翻车**。matplotlib 默认字体不含中文，会画成一排方块；
  CJK 字体又常缺负号，负刻度也成方块。`scripts/combo_chart.py` 会先挑系统里真实存在的中文字体、
  关掉 `unicode_minus`，找不到字体就报错而不是出一张豆腐块图。HTML 截图则靠 `--font` 里的中文字体栈。

版本已固定并实测可用：G2 `5.4.8`、G6 `5.1.1`、S2 `2.7.2`，
走 `https://unpkg.com/@antv/<pkg>@<ver>/dist/<pkg>.min.js`。

## 复杂 / 分析型图表清单

用户给了一张参考图、或者需求里出现「双轴、参考线、阈值、标注、复刻这张图」时，动手前逐条对一遍，
每一条都要在图上找得到落点，缺一条就是没做完：

1. **轴**：几根 y 轴？各自单位、范围是否固定？两轴的哪个刻度要对齐？x 是类目还是连续数值？
2. **系列**：每个系列是线 / 柱 / 面积？画在哪根轴上？线要不要平滑、多粗？
3. **条件样式**：有没有按正负、阈值、分组改颜色？辅助系列是否做浅？
4. **参考线**：竖线（关键点位）、横线（50%、零线、目标值）各几条？线型、颜色、标签文字和位置（旋转与否）？
5. **标注**：哪些点要打数值？格式（`72%`）、颜色、偏移，会不会压线（压线就给文字描底色边）？
6. **文字**：标题、轴标题、图例位置、脚注口径与免责声明，一条不能少；示例数据要写明「示例数据」。
7. **字体与语言**：中文是否正常、衬线还是无衬线（参考图是宋体就用 `--font` 的衬线栈）？
8. **交付形态**：对话内嵌 → 08 包进 renderer；要图片文件 → `scripts/export-png.sh` 截图，
   离线或要和 matplotlib 原图一模一样 → `scripts/combo_chart.py`（改 JSON 规格即可）。
9. **自检**：真渲染一次再看（能截图就截图），对照参考图逐项核：轴范围、参考线位置、标签有没有重叠或被裁。

```bash
# 例：用 matplotlib 出 PNG（spec.json 字段见脚本里的 DEMO）
python3 scripts/combo_chart.py spec.json out.png
# 例：把任意 render 截成 PNG（2x 清晰度，可选 dark）
bash scripts/export-png.sh renders/08-combo-dual-axis.html out.png 1024 680
```

## 输出格式

最终回复里每个 HTML render 都必须包在 renderer 围栏里 —— 起始行逐字是
` ```html type="renderer" `，结束行是 ` ``` `，各自独占一行。
裸 HTML、普通 `html` 代码块或别的包裹方式都不会被渲染。

```html type="renderer"
<html style="margin:0;padding:0;">
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width,initial-scale=1" />
  <title>按主题命名的页面标题</title>
  按任务生成的内容
</html>
```

文档级 `<title>` 要有且非空，按内容命名（如「二分查找过程演示」），
不要 `Untitled`、`可视化` 这类占位名 —— 它会成为网页标签页和书签的名字。
可见标题、SVG 里的 `<title>`、图表库的 title 配置都替代不了它。
同一文档只写一个，后续 renderer 片段不重复。

先给文字结论，再给图。数据要内联、自包含，不依赖外部数据源。

用户明确要 G2/G6 的配置代码时，可以另外给一个小写 `g2` / `g6` 代码块，
只放 spec，不要初始化代码、HTML、CSS 或 renderer 包裹。

## 不接的活

- **地图**：地理轨迹、行政区划、经纬度点位、地图热力，以及 AntV L7，全部不做。
- **附件**：PDF / PPT / Word / Excel 请走对应的文件能力，renderer 不是附件，别拿它冒充。
  图表类的 PNG 例外：用 `scripts/` 生成真实图片文件，作为文件交付（不要包进 renderer）。
- **美术**：海报、头像、壁纸、写实图片、艺术插画。
- **编数据**：真实数字、年份、人物、事件只能来自用户提供的材料或已核验的结果；
  自己造的示例数据必须在脚注里写明「示例数据」。
  依赖原图作证据时保持原图原貌，示意图要显式标注「示意」。
